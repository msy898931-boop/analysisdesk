# AnalysisDesk

منصّة تحليل فني للأسواق، مبنية بالكامل حول الذكاء الاصطناعي، وتعمل على **بيانات سوق حقيقية**.

An AI-driven market analysis desk built on **real market data**.

كيف بُني، وليش كل طبقة منفصلة، ووين الحدود — في [`ARCHITECTURE.md`](ARCHITECTURE.md).
وعرض المشروع (عربي/إنجليزي، ملف واحد بلا اعتماديات) في [`web/pitch.html`](web/pitch.html)،
ويُخدَم من الخدمة الحيّة على `/pitch`.

---

## الفكرة / What it does

تدخل رمز أصل وإطاراً زمنياً، فتحصل على:

- **قراءة اتجاه** (شراء / بيع / محايد) مع درجة توافق المؤشرات
- **وقف خسارة وستة أهداف** محسوبين من تقلب السوق الفعلي (ATR) ومستويات
  ارتكاز حقيقية، لا من أرقام ثابتة. كل هدف يحمل مصدره: **مستوى ارتكاز فعلي**
  حين يوجد، أو **امتداد تقلّب** حين تنفد المستويات — والاثنان مكتوبان صراحةً
- **تفسير بالذكاء الاصطناعي** يشرح القراءة بالعربية أو الإنجليزية
- **سجل قواعد شفّاف**: كل نقطة في التقييم مسنَدة إلى القاعدة التي أنتجتها
- **تحذيرات صريحة** حين تكون الصفقة ضعيفة (هدف قريب، مخاطرة/عائد منخفضة)

Supported assets: forex, crypto, commodities, indices and stocks — 10 instruments
across 5 timeframes (5m → 1wk).

## كل رقم يحمل مصدره / Every number carries its source

هذه القاعدة هي سبب وجود حقل `instrument` و`spot` و`anchor` في كل استجابة:

- الذهب متاح **بشكلين** لأن المتداولين لا يتفقون على رقم واحد:
  - **الذهب (سبوت)** `XAUUSD` — **هذا ما تراه عند وسيطك**. للرسم البياني
    نستخدم سوق الرمز المغطّى بالذهب (`PAXG/USD`) لأن لا يوجد مصدر شموع
    مجاني ومباشر لـ XAU/USD.
  - **الذهب الآجل** `GC=F` — عقد COMEX، وسعره يختلف عن السبوت بمقدار
    **الأساس** (الفائدة + علاوة العقد)، وهو معروض صراحةً.
- **الإرساء على السبوت.** الرمز المغطّى يتداول بعلاوة صغيرة (~0.2%) عن
  XAU/USD، فلو رُسمت شموعه كما هي لَكانت كل المستويات (الدخول، الوقف، الهدف،
  الدعم، المقاومة) على مقياس الرمز لا على مقياس شاشتك. لذلك نُعيد قياس
  الشموع بمعامل واحد (السبوت الحيّ ÷ آخر إغلاق) فتصبح كل المستويات على مقياس
  وسيطك. المؤشرات النسبية (RSI، ATR%، موقع بولنجر) **لا تتغير** لأن المعامل
  يُختصر. والتحويل **مُعلَن** في حقل `anchor` وعلى البطاقة — لا إرساء صامت.
- إذا انحرف الرمز عن السبوت بأكثر من **1.5%**، لا نُرسيه (كيلا نختلق سعراً)،
  ونحذّر على البطاقة أن المستويات مستويات البروكسي لا السبوت.
- البطاقة تعرض: اسم الأداة الصريح، ونوعها (سبوت/آجل)، ومصدر الشموع،
  و**سعر السبوت الحيّ** من Swissquote، ومقدار الإرساء بالنسبة المئوية.
- إذا تعذّر المصدر الأساسي للشموع، ينتقل النظام إلى البديل تلقائياً؛ وإذا
  تعذّر الجميع، تُعلَن الحقيقة: "تعذّر قراءة بيانات السوق" — ولا يُعرض رقم بديل.

مصادر الشموع (بلا مفاتيح): **Kraken** أولاً (كل الإطارات مباشرة + ٧ سنوات
تاريخ)، ثم **Coinbase** (يُجمَّع اليومي إلى أسابيع عند الحاجة). والسبوت الحيّ
من **Swissquote**، ثم `gold-api`.

## تشغيله بشكل دائم / Keeping it running

هذه البيئة **ما فيها نظام خدمات**: PID 1 هو الوكيل، `systemd` معطّل، ولا cron
ولا supervisor. فالحلقة التي تعيد التشغيل موجودة في السكربتات:

| الأمر | الوظيفة |
|---|---|
| `scripts/start.sh` | يشغّل الخادم منفصلاً (detached) مع حراسة تعيد تشغيله. آمن للتكرار. |
| `scripts/status.sh` | يخبرك: الحراسة شغّالة؟ والخدمة تُجيب؟ ومفتاح الذكاء الاصطناعي فعّال؟ |
| `scripts/stop.sh` | يوقف الحراسة ثم الخادم (بالترتيب، وإلا أعادت الحراسة تشغيله). |

الحراسة تعيد التشغيل عند أي خروج (اختبرتُها بـ`kill -9`). و`flock` يضمن
**نسخة واحدة فقط** مهما شغّلت `start.sh`.

**الحد الحقيقي:** لو أُعيد تدوير الحاوية نفسها، لا شيء داخل الحاوية ينجو —
لازم تشغّل `scripts/start.sh` مرة بعد كل إعادة تشغيل للساندبوكس. السكربت
يركّب المتطلبات الناقصة تلقائياً إن مُسحت، وهذه هي الحالة التي لا تستطيع
الحلقة الداخلية إصلاحها بنفسها.

المفتاح يُقرأ من `.env` (مستثنى من git، صلاحياته 600). المجلد `web/` فقط
مكشوف للشبكة، فلا `.env` ولا `.runtime/` يُوصلان من الخارج.

## النشر / Deploying

الملفات جاهزة ومُختبرة: `Dockerfile`، `render.yaml`، `.dockerignore`، `.env.example`.
التطبيق **يشتغل بلا قرص دائم**: الكاش والحدّ بالمذاكرة، وملف التنبيهات (SQLite)
يُنشأ على قرص الحاوية. على الخطة المجانية بلا قرص مثبّت، هذا الملف **يُمسح عند
إعادة النشر/التشغيل** — فالتنبيهات المسلَّحة تُبنى من جديد. `/api/status` يقول
`store.durable: false` بصراحة. لِتسليكها، اضبط `DESK_DATA_DIR` على قرص مثبّت.

**الطريق الأسرع (Render):**

1. أنشئ ريبو فارغ على GitHub باسم `analysisdesk`.
2. ادفع الكود:
   ```bash
   git remote add origin https://github.com/<user>/analysisdesk.git
   GIT_TERMINAL_PROMPT=0 git push https://${GITHUB_TOKEN}@github.com/<user>/analysisdesk.git main
   ```
3. في Render: **New → Blueprint** → اختر الريبو. `render.yaml` يبني الباقي.
4. أضف `GROQ_API_KEY` في Environment (اختياري: بدونه يرجع للتفسير المحسوب).

**بـDocker محلياً:**
```bash
docker build -t analysisdesk .
docker run -p 8080:8080 -e PORT=8080 -e GROQ_API_KEY=... analysisdesk
```

**ملاحظة الخطة المجانية:** النوم بعد ~١٥ دقيقة خمول، ويصحو مع أول طلب
(cold start). لأن ما في حالة على القرص، الصحوة تكلّف **زمن لا صحة**.

## المبدأ الأساسي / The core principle

هذه المنصّة مبنية على عكس ما تفعله المواقع التي تعد بأرباح مضمونة:

1. **لا يوجد أي وعد بالربح.** كلمة "توافق المؤشرات" تعني اتفاق المؤشرات المستقلة،
   وليست احتمال ربح. لا يظهر أي رقم لا يمكن تتبّعه إلى صيغة.
2. **المحرّك هو مصدر الحقيقة، والموديل يشرح فقط.** كل مقارنة (مثل `price > EMA20`)
   تُحسب مسبقاً وتُعطى للموديل كحقيقة جاهزة، فلا يعيد اشتقاقها.
3. **حارس تحقّق يرفض كلام الموديل** إذا اخترع رقماً، أو وعد بربح، أو عكس علاقة.
   عند الرفض يعود النظام إلى جملة محسوبة من نفس الحقائق.
4. **الفشل يُعلَن ولا يُخفى.** إذا تعذّر قراءة السوق، يرجع النظام خطأ صريحاً
   (`تعذّر قراءة بيانات السوق`) ولا يعرض أي قيمة افتراضية مطمئنة.

## التشغيل / Running

```bash
pip install -r requirements.lock      # the pinned, hashed set the image uses
uvicorn app.main:app --host 0.0.0.0 --port 12000 --no-proxy-headers
```

`--no-proxy-headers` keeps uvicorn from rewriting the client address out of
`X-Forwarded-For`; the app decides for itself whether to read that header, via
`DESK_TRUST_PROXY` (off unless a proxy you control is in front).

`requirements.txt` declares the ranges; `requirements.lock` is the resolved,
hash-pinned form of them and is what the Docker image installs. `python
scripts/check_lock.py` proves the two still agree.

ثم افتح `http://localhost:12000`.

Groq مفتاح اختياري: إن لم يوجد `GROQ_API_KEY`، تعمل المنصّة كاملة وتبني التفسير
من المحرّك الحسابي بدلاً من الموديل. وإن انتهت حصة الموديل، تنتقل تلقائياً إلى
موديل بديل، ثم إلى التفسير المحسوب — مع ذكر السبب في الحقل `note`.

```bash
export GROQ_API_KEY=...              # اختياري
export ANALYSIS_MODELS="openai/gpt-oss-120b,qwen/qwen3.8-27b"   # اختياري
export RATE_LIMIT_PER_MIN=60         # اختياري — طلبات لكل IP بالدقيقة
export DESK_TRUST_PROXY=1            # بس إذا في proxy بتحكمو بيضيف آخر hop
export DESK_API_KEY=...              # اختياري — مفتاح إلزامي على كل طلب
export ALERTS_TOKEN=...              # اختياري — سرّ خدمة لـ/api/alerts* (بلاها 503)
```

## الـ API

| المسار | الوصف |
|---|---|
| `GET /` | الواجهة |
| `GET /api/health` | حالة الخدمة والموديل |
| `GET /api/status` | تشخيص أعمق: مدة التشغيل، عدد الطلبات، النسخة المنشورة، حجم الكاش |
| `GET /api/symbols` | قائمة الأصول والأطر الزمنية |
| `GET /api/analyze?symbol=EURUSD=X&interval=1h&lang=ar` | التحليل الكامل |
| `GET /api/backtest?symbol=EURUSD=X&interval=1h&step=5` | سجلّ المحرّك على بيانات تاريخية (مشي أمامي، بلا نظرة للمستقبل) |
| `GET /api/news` | عناوين حديثة من مصادر RSS عامة بلا مفاتيح |
| `GET /api/alerts?chat_id=…` | التنبيهات المسلَّحة لحساب معيّن (بدها `x-alerts-token`) |
| `POST /api/alerts?chat_id=…&symbol=…&price=…&direction=BUY` | تسليح تنبيه عند عبور مستوى (بدها `x-alerts-token`) |
| `DELETE /api/alerts/{id}?chat_id=…` | حذف تنبيه يملكه صاحبه (بدها `x-alerts-token`) |
| `GET /api/candles?symbol=BTC-USD&interval=1d` | شموع للرسم |

مثال:

```bash
curl "http://localhost:12000/api/analyze?symbol=GC=F&interval=1h&lang=ar"
```

### الحماية / Guard

نقاط التحليل بتصرف حصة الموديل، فهي **محدودة لكل IP** (`RATE_LIMIT_PER_MIN`،
افتراضياً ٦٠ بالدقيقة). وهوية العميل للحد هي **عنوان الـsocket**، مو هيدر: هيدر
`X-Forwarded-For` بيكتبه العميل، فبينقرأ **بس** لما ينضبط `DESK_TRUST_PROXY` —
وهاد بيضبطه blueprint تبع Render، لأن راوتر Render فعلاً بيضيف العميل الحقيقي
كآخر hop. بلاها، هيدر مزوّر ما بيقدر يخترع هوية جديدة كل طلب. وإذا انضبط
`DESK_API_KEY`، **كل** طلب لازم يقدّمه —
الصفحة المرفقة كمان، لأن الصفحة العامة ما بتقدر تحمل سرّاً بلا ما يصير علنياً.
كان في استثناء للصفحة عبر `Sec-Fetch-Site: same-origin`، بس المتصفح بيكتبه
والسكربت كمان بيكتبه، فكان **تجاوزاً مو مصادقة**؛ انشال والبوابة صارت
fail-closed. عملياً: خلّي `DESK_API_KEY` فاضي إذا بدك الصفحة العامة تشتغل
(هاي حالة الإنتاج)، وانضبطه بس لما الـ API للاستخدام البرمجي. بلا
`DESK_API_KEY` الـ API مفتوح لكن محدود. الحد لكل عملية على حدة (بالذاكرة)، يعني
إعادة التشغيل بتصفّره — هاد مذكور صراحةً، مو مخبّى.

و`/api/alerts*` إلها بوّابة تانية: **سرّ خدمة** (`ALERTS_TOKEN`، بينبعت
`x-alerts-token`). هي خدمة-لخدمة — البوت هو العميل الوحيد، والصفحة المرفقة ما
بتلمسها. الـ`chat_id` **معرّف مو سرّ** (بيتسرّب عبر مجموعات تيليجرام والرسائل
المُعاد توجيهها)، فما بيصلح يكون المصادقة الوحيدة؛ هو بس بيختار الصفوف.
بلا `ALERTS_TOKEN`، الـendpoints بترجّع **503 (مقفلة)** — مو مفتوحة. `/api/status`
بيقول `alerts_configured` حتى يفرّق العميل بين «مقفلة» و«توكن غلط» بلا تخمين.

## الأمان / Security

- **كل نص من السيرفر بينزل للمتصفح عبر `esc()`** في `web/app.js`، والسرد
  الآلي بينضاف عليه تنظيف markup بالسيرفر (`_strip_markup` في `app/ai.py`).
- **رؤوس أمان على كل استجابة**: `Content-Security-Policy` (`script-src 'self'`
  — بيمنع أي سكربت inline)، `X-Content-Type-Options: nosniff`،
  `X-Frame-Options: DENY`، `Referrer-Policy: no-referrer`.
- **الحاوية بتشتغل بمستخدم غير root** (`desk`, uid 10001).
- **الرمز مُتحقَّق منه قبل أي نداء خارجي**: `_valid_symbol` بيرفض أي شكل مو
  رمز Yahoo صالح (`^[A-Za-z0-9.^=_-]{1,20}$`)، فلا مسافة ولا `/` ولا `..`
  يوصل للـURL upstream. مو SSRF — المضيف ثابت — بس إدخال غير محقّق كان يكلّف
  نداءً ضايعاً ويرجع صدىً بالنص.
- **`/docs` و`/redoc` و`/openapi.json` مطفأة عن قصد.** Swagger الافتراضي
  بيحمّل JS من CDN، وسياسة `script-src 'self'` بتحجبه — فالصفحة كانت ترد 200
  كقشرة فاضية (إشارة «كل شي تمام» فوق صفحة ما بتشتغل). الـAPI موثّق بالـREADME
  بدلها.
- **فحص ثغرات في الكود والتاريخ**: CodeQL (security-and-quality) + gitleaks
  على كامل التاريخ في `.github/workflows/security.yml`، مع `pip-audit` و
  `bandit` في الـCI.
- **سياسة الإفصاح في [`SECURITY.md`](SECURITY.md)**.
- **`pip-audit` نظيف** و**`bandit` نظيف** (لا نتائج medium/high).

```

  signals.py     محرّك القرار الحتمي + التحذيرات ثنائية اللغة

  alerts.py      كشف عبور المستوى + إرسال تيليجرام (مطفأ افتراضياً)
  schemas.py     نماذج pydantic لاستجابات الـAPI — العقد موثّق ومُتحقَّق منه
  main.py        واجهة FastAPI + رؤوس الأمان + حدّ الطلبات
web/index.html   الواجهة (عربي/إنجليزي، بلا أي اعتماد خارجي)
web/pitch.html   عرض المشروع (عربي/إنجليزي، بلا سكربت — التبديل بـCSS) يُخدَم على /pitch
web/lib.js       دوال نقية (esc، fmt، priceDecimals) يشترك بها المتصفح واختبارات node
web/app.js       سكربت الواجهة (module خارجي عمداً — CSP بيمنع inline)
web/app.test.mjs ٨ اختبارات للدوال النقية عبر `node --test`
web/dom.test.mjs ٧ اختبارات تربط الواجهة (تشغّل app.js بمتصفح وهمي)
tests/           اختبارات على المسارات الحقيقية، بلا محاكاة
scripts/         فحص النشر + تمريرة تنبيهات لمرة واحدة (تناديه من مجدول؛ ليس daemon)
pyproject.toml   مصدر واحد: الاعتماديات + إعدادات ruff/pytest/coverage/mypy
ARCHITECTURE.md  الطبقات وتدفّق البيانات والحدود الصريحة
.github/         CI + قالب الـPR + مراقبة النشر
```

## الاختبارات / Tests

```bash
python -m pytest tests/ -m "not network"   # اللي بيشتغل بالـCI — بلا شبكة
python -m pytest tests/                    # مع اختبارات الشبكة الحيّة
```

الاختبارات تعمل على الكود الحقيقي: محرّك الإشارات، رياضيات المؤشرات، وحارس
التحقّق، وواجهة الـ API مع بيانات سوق حيّة. لا توجد أي mocks.

الاختبارات اللي بتلمس مصادر خارجية معلَّمة بـ`@pytest.mark.network` ومستثناة
من الـCI: بناء أحمر لازم يعني «إحنا كسرنا شي»، مو «مصدر بطيء».

### الفحوصات / Checks

بوابة واحدة لكل شي: `make check` (تشغّل الـlint والأنواع والأمان والاختبارات
وواجهة node — نفس اللي بالـCI بالضبط). أو فردياً:

```bash
ruff check app/ tests/ scripts/
mypy
bandit -q -r app/ scripts/ -ll
pip-audit -r requirements.lock
```

كلها بتشتغل بالـCI على Python 3.11 و3.12 (`.github/workflows/ci.yml`)، وفحص
ثغرات منفصل (CodeQL + gitleaks) في `.github/workflows/security.yml`.

## حدود صريحة / Honest limits

- التحليل تقني فقط؛ لا يشمل الأخبار أو الأساسيات.
- المؤشرات متأخرة بطبيعتها؛ هذا تحليل، وليس توقّعاً.
- البيانات من مصدر مجاني عام، وقد تتأخر أو تنقطع.
- **الأخبار عناوين فقط** — RSS بيجيب العنوان والرابط والناشر والوقت، بلا نص
  الخبر. يعني «قراءة الأخبار» هنا = عناوين، ولا ادّعاء لمشاعر أو تفسير.
- **الـbacktest سجلّ، مو وعد.** الأرقام اللي بيطلعها (نسبة الإصابة، التوقّع
  بالـR، أقصى تراجع) هي **قياس على بيانات مضت**، والحكم فيها سلبي بصراحة لما
  يكون سلبي. التفاصيل بالـ`CAVEATS` جوا `app/backtest.py`.
- **الحالة الدائمة على Render المجاني بلا قرص ثابت**: ملف الـSQLite بيعيش على
  قرص الحاوية اللي بينمسح عند إعادة النشر/التشغيل. التنبيهات بتضيع عند إعادة
  التشغيل. الحل الجاهز: `DESK_DATA_DIR` على قرص مثبّت (Render Disk) أو قاعدة
  خارجية. لحد ما ينضبط هيك، التنبيهات بتنبنى من جديد بعد كل إعادة تشغيل.
- **حلقة التنبيهات مطفأة بالإنتاج، عن قصد — ومكتوب صراحةً.** الـAPI بيقدر
  يسجّل تنبيهات، و`scripts/run_alerts.py` بينفّذ تمريرة واحدة، بس **ما في
  مجدول بيناديها** على الخطة المجانية: Render المجاني بلا cron jobs، والحاويات
  منفصلة، والمخزن مؤقت. فالتنبيهات **ميزة مسلَّحة محلياً، مو خدمة شغّالة**.
  لِتشغيلها فعلاً بدك مخزناً دائماً **و** مجدولاً خارجياً (`ALERTS_ENABLED=1`
  + نداء مجدول للـendpoint). لحد ما ينضبط هيك، `/api/alerts` بترجّع
  `delivery_on: false`، وما في شي بيدّعي غير هيك.
- **نسخة واحدة (worker) عن قصد**: الكاش وعدّاد الحد بالمذاكرة. تشغيل أكثر من
  worker بيعطي عدّاد حد لكل worker على حدة (الحد الفعلي بيتضاعف) وكاش لكل
  واحد. صحّتها تحتاج مخزن مشترك (Redis) — مو موجود اليوم، ومذكور بدل ما يُخبّى.
- **هذا تحليل تقني آلي وليس توصية استثمارية، ولا ضماناً لأي نتيجة.**

## مراقبة النشر / Watching the deployment

خدمة Render المجانية **بتنام بعد ١٥ دقيقة بلا زوار** وبتصحى لحالها. هاد طبيعي،
مو عطل. الفحص التالي بيخبرك **إذا الموقع نايم**، **بدون ما يوقّظه**:

```bash
python3 scripts/check_deploy.py            # تقرير مباشر
python3 scripts/check_deploy.py --json     # للآلات
python3 scripts/check_deploy.py --notify   # تنبيه تيليجرام عند مشكلة حقيقية
```

### ليش `/robots.txt`؟

لأنه **الفحص الوحيد اللي بيشوف بدون ما يتدخّل**. لما الخدمة نايمة، Render
بتردّ على `/robots.txt` بنفسها (Disallow all) — والرد **ما بيوصل للتطبيق وما
بيوقّظه**. أي مسار تاني، `/api/health` مثلاً، **بيوقّظ الخدمة**.

> **فحص بجدول كل ٣٠ دقيقة على `/api/health` بيوقّظ الخدمة كل مرة وبياكل الـ٧٥٠
> ساعة الشهرية. الفحص بيدمّر الشي اللي بيقيسه.**

### الحالات الثلاث

| الحالة | المعنى | تنبيه؟ |
|---|---|---|
| `AWAKE` | التطبيق ردّ على `/robots.txt` بـ404 JSON | ✅ إذا `health != ok` |
| `ASLEEP` | Render ردّت بنفسها — طبيعي بالمجاني | ❌ لا |
| `UNKNOWN` | الطلب ما خلص أبداً | ⚠️ **نعم** — مو "كل شي تمام" |

**قراءة فاشلة بتقول `UNKNOWN`، وما بتنعرض أبداً كـ"كل شي تمام".**

### فحص استهلاك الساعات

```bash
python3 scripts/hours_audit.py --log deploy-watch.jsonl
python3 scripts/hours_audit.py --log deploy-watch.jsonl --services 2
```

⚠️ **Render ما بتعرض استهلاك الساعات عبر الـAPI** — لا usage ولا billing ولا
quota. الرقم الموثوق **بس بالـDashboard**. فالسكربت **بيقول هاد صراحةً** وبيقدّم
**توقّعاً** من قراءاته، مو رقم دقيق مخترع.

**٧٥٠ ساعة لكل مساحة عمل، مو لكل خدمة.** خدمة تانية شغّالة ٢٤/٧ = ٧٢٠ ساعة،
يعني لحالها بتاكل السقف.

### الأتمتة

`.github/workflows/deploy-watch.yml` بيفحص **على كل دفعة (push) لـmain**، وكل
٣٠ دقيقة كـ**احتياطي بأفضل جهد**:

- **على push** — بيثبت إنه **المراجعة اللي دفعتها هي اللي شغّالة** (بيقرأ
  `RENDER_GIT_COMMIT` من `/api/status` وينتظر النشر)، **وبيتأكد إنه العملية
  الجديدة ما سجّلت ولا خطأ غير متوقّع** (`--max-errors 0`). ضوء أخضر بيقول بس
  "في شي شغّال" هو نفس الإنذار الكاذب اللي هالمنصّة بترفضه.
- **بينبّه** عند `UNKNOWN`، أو `AWAKE` + غير سليم، أو **إذا الرصد نفسه سكت**
  (آخر قراءة أقدم من ١٢ ساعة).
- **ما بينبّه** عند النوم — لأنه طبيعي.
- بلاغ واحد مُعاد استخدامه، **بينغلق تلقائياً** عند التعافي.
- **بيكلّف صفر ساعات** على الجدولة — لأنه ما بيوقّظ الخدمة.

> ⚠️ **جدولة GitHub "أفضل جهد" فعلاً، مو على الورق.** هالـworkflow انضاف بـcron
> كل ٣٠ دقيقة وطلع **صفر تشغيلات مجدولة**، بينما ريبو تاني بـcron كل ٥ دقايق
> اشتغل كل ٤–٦ ساعات بس. **مراقب ما بيشتغل بيسكت بنفس طريقة الخدمة السليمة** —
> فلهيك في trigger على push، ولهيك الرصد بيراقب نفسه (`--gap-threshold`).

لتشغيله يدوي مع اختبار التنبيه: Actions ← deploy-watch ← Run workflow ← ✅ `force_alert`

### `/api/status` — الفرق عن `/api/health`

`/api/health` بيقول "أنا حيّ". `/api/status` بيجاوب الأسئلة اللي بعدها:

| الحقل | المعنى |
|---|---|
| `uptime_s` | كم مضى على هالعملية — الصغير يعني "انعاد تشغيلها"، مو "ما صار شي" |
| `served` | كم ردّ قدّم هالعملية |
| `commit` | النسخة المنشورة فعلاً (من `RENDER_GIT_COMMIT`) |
| `cache` | حجم كاش الأسعار — بيفرّق الاستعمال العادي عن مسح |
| `tracked_clients` | عدد العملاء المميّزين بآخر دقيقة (نفس مجموعة حدّ المعدّل) |
| `errors` | عدد الأخطاء غير المتوقّعة منذ التشغيل، مصنّفة بالنوع (تجميعي فقط) |

**كل الحقول محلية للعملية وبتنصفّر عند إعادة التشغيل** — `uptime_s` هو الدليل.

### تتبّع الأخطاء / Error tracking

**قبل:** أي خطأ غير متوقّع كان يطلع ٥٠٠ فاضي **وما يترك أثر بأي مكان** — لا لوج
ولا عدّاد. **هلّق** (`app/errors.py`):

- **سطر JSON واحد على stdout** لكل خطأ غير متوقّع — وRender بتحفظ stdout،
  فهاد **السجل الدائم**. التتبّع الكامل (traceback) بيضلّ باللوج.
- **العميل بياخد ٥٠٠ عام + `X-Request-Id`** — **بلا traceback ولا مسار ولا رسالة**.
  الـid بيكفّي لتلاقي السطر الكامل باللوج.
- **الأسرار بتنقّح** قبل الكتابة: أي قيمة لـ`GROQ_API_KEY` أو `DESK_API_KEY` أو
  `TELEGRAM_BOT_TOKEN` بتظهر بالنص بتصير `***`.
- **خريطة الأنواع محدودة** (٢٠ + دلو `_other`) — حلقة أعطال ما بتكبّرها بلا حدّ.
- **`/api/status` بيعرض العدد التجميعي فقط** — أنواع وأعداد، **بلا رسائل ولا مسارات**.

> **مهم:** عطل مصدر السوق **مو خطأ عندنا**. المصدر واقع = `502` مع السبب، و**ما
> بينعدّ** هون. لو انعدّ، العدّاد بصير ضجّة وبيتجاهله القارئ.

> **ليش بلا Sentry؟** تتبّع خارجي بيطلّع stack traces وسياق الطلبات وبيانات المالك
> لحساب خارجي — **قرار ما بتاخده هالمنصّة عنك**. الحل: لوج منظّم على stdout
> (Render بتحفظه) + ملخّص محدود بالذاكرة. **بلا حساب خارجي وبلا تسريب بيانات.**
